# CareerPilot CN V3.3 简历内容策略

日期：2026-08-07

## 用户问题

央国企简历不能沿用互联网简历“堆技术栈”的写法。给非技术 HR 和业务面试官阅读时，核心是
候选人解决了什么问题、承担了什么责任、如何协同推进、形成了什么交付或结果。原有五套主题
主要是视觉差异，选择成本高，也不足以表达不同招聘市场的阅读逻辑。

## 三种策略

| 策略 | 核心阅读者 | 经历表达公式 | 技术细节规则 |
|---|---|---|---|
| 央国企成果导向 | 非技术 HR、业务面试官、综合评价者 | 问题或任务 → 个人责任 → 关键行动与协同 → 交付或可验证结果 | 只保留解释解决问题所必需的技术 |
| 互联网工程导向 | 技术面试官、工程负责人 | 技术或业务挑战 → 个人所有权 → 方案与关键取舍 → 性能、质量或业务影响 | 关键框架和架构必须绑定行动、约束或取舍 |
| 科研学术导向 | 研究院、研发中心、算法研究评审 | 研究问题或工程目标 → 方法与实验设计 → 个人贡献 → 论文、专利、指标或转化结果 | 方法和模型用于说明有效性，名称本身不算成果 |

第三种选择科研学术，而不是再增加配色主题：参考样例中有研究生教育、论文、专利、研究成果等
独立阅读逻辑，这类岗位既不同于一般央国企综合评价，也不同于互联网工程筛选。

## 从参考图提炼的央国企规则

- 实习可按“业务需求对接 → 工程化落地 → 效果测试”组织，也可按“工作内容 → 工作成效”组织。
- 项目应有结尾，优先三条内讲清问题、个人动作和结果；技术名词只在解释动作时保留。
- 结果不限于百分比：交付、验收、稳定运行、风险消除、流程闭环、文档沉淀和协同成果都可以，
  但必须来自已确认 Fact。
- 学生干部、社团、志愿服务和校园实践可以证明组织、协调和综合素质；缺少对口实习的综合岗可前置。
- 技能区用于让 HR 抓住证书、岗位相关技能和有证据的特长；不列长工具清单，不写无依据的“精通”。

## 产品边界

- 参考图只学习内容结构和版式，不学习其中的学校、单位、指标、荣誉、身份、头像或作者关系。
- 内容诊断只计算整个 Fact 组合中的经历数和独立结果数，是组合层代理指标，不声称每条结果属于某条经历。
- 岗位简历的“生成证据约束候选改写”会消费当前策略，对每条 Fact 标记可用或待补证据；纯技术栈在三种策略下分别要求补充成果闭环、工程语境或科研成果语境。
- 多分句候选改写只能重排原词项，必须逐条接受；策略不能借改写新增任何问题、责任、指标或成果。
- 系统不会根据技术 Fact 数量自动判断用户在投互联网；目标单位与岗位语境必须由用户确认。
- 所有实质改写仍受 Fact Diff、逐条确认、30% 上限、预览哈希和 manifest 门禁约束。
- 旧两代风格配置只读迁移；不会在加载时修改用户文件。
